## 2. Расхождение с PDF

PDF утверждает «511 тестов» для v0.16. Фактически в `main` для v0.16 —
**348**. Разница объясняется тем, что цифра 511 относится к дереву вместе с
v0.11–v0.15, которых в `main` нет (см. §3). Это не косметика: любые отчёты о
покрытии, которые цитируют 511, описывают **другое дерево**.

## 3. Главный интеграционный разрыв — PR №1

`gh pr list` → открытый PR №1 «v0.11–v0.15: Compound Information Machine +
unified CLI» (head `arena/aa17ff3d-bunyod`, +11275/−21, 137 файлов).

**Критический факт:** `git merge-base main FETCH_HEAD` завершается с кодом 1 —
у ветки PR и у `main` **нет общего предка**. Это два независимых корня
истории, а не «ветка, отставшая от main». Следствия:

* `git merge` влил бы 11 275 строк как конфликт «добавлено с обеих сторон»
  и переписал бы историю (либо потребовал `--allow-unrelated-histories`
  с ручным разрешением 137 файлов);
* автоматическая проверка «ничего не потеряно» при таком слиянии невозможна —
  сравнивать не с чем, diff пустой по определению.

Поэтому v0.17 **не сливает** PR №1, а интегрирует его **на уровне данных**:
форматы `rasm-cim-kb/1` и `rasm-cim-learned/1` читаются напрямую и
импортируются в граф v0.16 с сохранением происхождения (см.
`docs_v17/ARCHITECTURE.md`, План A). Ветка PR остаётся доступной как
источник данных и как история решений; её код в `main` не попадает.

Что реально взято из PR №1 в v0.17 (проверено чтением `git show FETCH_HEAD:…`):

| Артефакт | Как используется |
|---|---|
| `rasm-cim-kb/1` (`meta.json` + `events.jsonl`, `store.py`) | читатель `interop/legacy.py` (torn-tail и битые строки воспроизводятся как в писателе) |
| `rasm-cim-learned/1` (`artifacts.py`) | `interop/learned.py`, включая проверку sha256 по `current.json` и ту же Laplace-арифметику (alpha=0.5) |
| `predicate_hints` / `alias_delta` | `routing.json` и алиасы сущностей (План A) |
| `rasm_cim_v11/data/demo_facts.jsonl` (34 факта) | тестовый fixture `tests_v17/fixtures/v11_demo_facts.jsonl` — реальные данные, не синтетика |
| словарь 8 отношений v0.11 + 5 функциональных v0.12 | таблица `interop/mapping.py` (явная, с отказом угадывать) |

## 5. Что нельзя измерить в этом окружении (INCONCLUSIVE, не «сделано»)

* **Python 3.14** — в песочнице 3.11.2. Совместимость с 3.14 не проверена.
* **ARM64 / Termux** (≈3 ГБ RAM, без root/GPU) — архитектура песочницы x86_64.
  Все заявления о Termux в v0.17 остаются проектными требованиями; измерений
  времени/памяти на устройстве нет.
* **Пользовательская база** — `~/.rasm-cim/kb.json` в окружении отсутствует,
  поэтому «миграция реальных данных» не выполнялась и не заявляется.
* **Качество языка** — в `main` нет корпуса с эталонной разметкой, поэтому
  intent/entity/coreference-метрики Плана B пока не имеют базы сравнения;
  в v0.17 они считаются только на том, что действительно есть (см.
  `docs_v17/TEST_REPORT.md`).

## 6. Решение по стратегии

1. `main` — единственная линия развития; v0.16 не переписывается.
2. Новые возможности — в новых пакетах (`rasm_cim_v17/…`), старые версии и
   публичные API сохраняются.
3. PR №1 — источник форматов и данных; его код не импортируется, чтобы
   v0.17 не зависел от невлитой ветки.
4. Каждый формат читается с явной версией схемы; неизвестная схема —
   отказ, а не «попробуем».
