## 2. Задачи, выборки, метрики, пороги

Формат ответа **одинаков для системы и модели** — JSON-объект:

```json
{"answer": "<строка или null>", "status": "ok|unknown", "evidence": ["<id>", "..."]}
```

Для RASM адаптер берёт это из `rasm-cim ask --json` (поля `text`, `status`,
`evidence`): `status` из `DIRECT|INFERRED` → `ok`, `UNKNOWN` → `unknown`.
Для модели тот же объект запрашивается промптом (раздел 4). Отказ
(`status="unknown"`) — **полноценный ответ**, а не ошибка; связки и отказы
никогда не смешиваются в одну метрику.

| Задача | Что делает система | n (видимые) | n (hidden) | Метрика | Порог «не хуже» |
|---|---|---|---|---|---|
| **T1 coref-bind** | по диалогу назвать референт местоимения | 100 | 15 | точность верного референта | RASM ≥ модель − 5 п.п. |
| **T2 coref-refuse** | понять, что референт не определён, и переспросить | 100 | 15 | точность отказа | RASM ≥ модель − 5 п.п. **и** ≥ 0.85 абсолютно |
| **T3 qa-abstain** | ответить по тексту; если ответа нет — сказать «не знаю» | 100 (50 отвечаемых / 50 нет) | 15 | точность на отвечаемых, точность отказа на неотвечаемых (раздельно) | RASM ≥ модель − 10 п.п.; абсолютно ≥ 0.80 |
| **T4 extraction** | извлечь из реплики тройку (субъект, класс, объект) | 100 реплик | 15 | precision / recall / F1 по тройкам | F1 ≥ модель − 10 п.п.; абсолютно ≥ 0.80 |
| **T5 json-format** | вернуть корректный JSON с нужными полями и типами | 120 (100 из T3 + 20 крайних) | 15 | доля валидных JSON с полным набором полей | ≥ модель − 5 п.п.; абсолютно ≥ 0.95 |
| **T6 coherence** | связность ответа T3 | 100 | 15 | доля связных по судье (раздел 5) | ≥ модель − 5 п.п. |

Обоснование порогов: при n=100 полуширина 95 % ДИ Уилсона около ±9 п.п., при
n=50 — около ±13 п.п. Порог меньше полуширины был бы неотличим от шума, поэтому
5 п.п. для n=100 и 10 п.п. для подвыборок n=50. Абсолютные пороги (0.80/0.85/0.95)
взяты как «пригодно к использованию», а не «лучше случайности».

Наборы T1/T2 собираются из уже сданных независимых наборов этапа аудита
(`audit_v1/data`, автор — тот же аудитор, разметка от 2026-11-27) плюс
дополнения до 100 кейсов на задачу; дополнения пишутся вручную. Наборы T3–T5
пишутся вручную с нуля. Генераторы не используются. Все наборы — разговорная
речь, опечатки, неполные фразы, смесь русского с таджикскими словами.

## 3. Базовые стратегии (обязательны)

* **B1 «всегда отказывать»** — `status="unknown"` на каждый кейс (нижняя граница
  по отказам, верхняя по потерям).
* **B2 «последнее имя»** — референт = последнее имя собственное в репликах до
  последней (для T1); для T3 — ответ = предложение текста с максимальным
  пересечением слов с вопросом; для T4 — регулярное извлечение по шаблону
  «X — это/— Y».
* **B3 «последнее имя нужного рода»** — для T1 (род по окончанию `-а/-я` →
  женский).

Базовые стратегии не используют базу знаний проекта и разметку.

## 4. Промпты для модели (зафиксированы, не использовались)

Один и тот же системный промпт для всех задач, меняется только блок задачи:

```
Ты — модуль обработки русского текста. Отвечай ТОЛЬКО JSON-объектом
{"answer": <строка или null>, "status": "ok"|"unknown", "evidence": []}.
Если ответа нет в данных — верни {"answer": null, "status": "unknown", "evidence": []}.
Не добавляй пояснений вне JSON.
```

Блок задачи (по одной строке, без примеров из наборов):

* T1: `Диалог: {dialogue}\nК какому объекту относится местоимение в последней реплике?`
* T2: `Диалог: {dialogue}\nОднозначен ли референт последней реплики? Если нет — status="unknown".`
* T3: `Текст: {text}\nВопрос: {question}\nОтветь по тексту или status="unknown".`
* T4: `Реплика: {sentence}\nВерни {"subject":…, "class":…, "object":…} в поле answer одной строкой JSON.`
* T5: `Вопрос: {question}\nВерни JSON с полями answer, status, evidence.`

Параметры генерации: `temperature=0`, `top_p=1`, `seed=20261127`, `n_predict=256`.
Промпт не меняется между наборами; примеры из hidden в промпт не попадают.

## 5. Судьи для T6 (связность)

Два независимых судьи-скрипта, оба не видят метки задачи и не знают, кто
отвечал:

* **J1 (структурный)**: ответ непустой, заканчивается знаком конца предложения,
  не содержит служебных маркеров (`null`, `None`, `undefined`, `[]`, `{}`,
  «не могу», «как ИИ»), не повторяет вопрос дословно, длина ≥ 3 слов.
* **J2 (содержательный)**: ответ упоминает объект вопроса (имя/класс из
  вопроса) и не содержит чисел/имён, которых нет ни в тексте, ни в вопросе.

Согласие J1/J2 считается каппой Коэна; если каппа < 0.4, метрика T6 помечается
как ненадёжная. Человеческая слепая разметка не проводилась (нет второго
человека) — это ограничение, а не «два человека».

  вердикт против модели — **НЕДОСТАТОЧНО ДАННЫХ**; абсолютные пороги и
  сравнение с базовыми стратегиями приводятся отдельно и не подменяют его.
