Исторический статус на момент аудита: этап 0 был заблокирован отсутствием корпуса;
базовые метрики ещё не измерялись. После разрешения пользователя подготовлен

Аудит проведён на коде `fc607083500b59a627235029e3b22ea1f4ca6e28`.

## Аудит исходного кода

- `modelforge/datasets/manager.py`: импортирует записи, удаляет пустые строки и
  точные дубликаты после приведения регистра и пробелов, делит записи с seed и
  проверяет точные пересечения между частями. NFC-нормализация, определение языка
  и поиск близких дубликатов не выполняются. Название лицензии передаётся как
  строка; подтверждение прав на тексты код не проверяет.
- `modelforge/model_builder/builder.py:207-214`: токенизатор обучается на
  переданных при создании модели текстах; для честного эксперимента в него
  следует передавать **только train**, а не весь исходный корпус.
- `modelforge/training/engine.py:223-247`: при пустой validation используется
  train, а при отсутствии датасета validation берётся из тренировочного seed-корпуса.
  Эти fallback-режимы непригодны для независимого базового замера.
- `modelforge/training/engine.py:135-152,350-351`: короткий поток повторяется,
  окна перекрываются, а во время обучения validation считается только на первых
  окнах. Для сопоставимого baseline нужно явно определить учёт всех символов,
  контекста, границ записей и спецтокенов и не подменять validation test-частью.
- `modelforge/evaluation/metrics.py:64-77`: метод оценки при наличии датасета
  предпочитает test, а не validation, и при отсутствии данных использует встроенный
  seed. Нужно не вызывать test для подбора и не использовать такой fallback.
- `modelforge/tokenizers/tokenizer.py`: текущий `UnicodeBPETokenizer` работает
  с символами Unicode, **не является byte-level BPE**. Незнакомые символы
  преобразуются в `<unk>`; стандартное декодирование пропускает их. Для метрик
  bits-per-character/byte необходимо учитывать эту потерю и точно определить
  знаменатель и обработку спецтокенов.
- `modelforge/training/engine.py:322-345,380-435`: накопление градиентов,
  warmup/cosine и early stopping уже присутствуют. Но best validation loss
  используется для решения об остановке, а сохраняются финальные веса, а не
  обязательно лучшие; расписание и неполные группы накопления нуждаются в отдельной
  проверке до заявления о корректности. RSS фиксируется снимками, не как пик.
- `modelforge/mobile/offline.py`: мобильный быстрый старт — отдельный небольшой
  экспериментальный trainer, а не тот же pipeline, что `TrainingEngine`; у него
  нет фиксированного validation/test и сохранения метаданных эксперимента,
  необходимых для данного исследования. Его возможности не следует считать
  доказательством работы модели на физическом телефоне.

## Данные и блокировка

В репозитории есть `DEFAULT_MULTILINGUAL_SEED_CORPUS` в Python-файле проекта,
который поставляется с корневой лицензией MIT (`LICENSE`). Это демонстрационные
строки о самом приложении, а не достаточно разнообразный русско-таджикский
корпус с документированным независимым происхождением. Они уже используются как
обучающие данные по умолчанию. Использовать их одновременно для независимой
validation/test и заявлять репрезентативное качество нельзя. Отдельного корпуса
с подтверждённым происхождением и пригодным распределением по двум языкам в
проверенных файлах репозитория не обнаружено.

Нужен предоставленный пользователем корпус с явным разрешением на использование
и сохранение результатов либо указание источника, где права подтверждены для
каждой части корпуса. Альтернатива — разрешение на явно помеченный синтетический
корпус, создаваемый для этого проекта; такой baseline будет только технической
проверкой, а не оценкой реального качества языка.
