# Измерение возможностей устройства

`modelforge doctor --capabilities` выполняет ограниченный CPU-пробник, печатает JSON и сохраняет его в `<home>/capabilities.json`. Опция `--output PATH` меняет путь. `GET /api/v1/system/capabilities` вызывает тот же сервис и возвращает JSON, но не сохраняет его. Вызов занимает до 55 секунд; его не следует выполнять одновременно с тяжёлой работой. `ModelForgeCore.capabilities()`, `ModelBuilder.get_capabilities()` и `TrainingEngine.get_capabilities()` используют общий сервис. Для настройки резерва, тайм-аута, кандидатов, batch и context используйте Python `measure_capabilities(ProbeConfig(...))`; конфигурация присутствует в отчёте. psutil теперь базовая зависимость; numpy нужен для реальных шагов.

Системная RAM — psutil, cgroup v2 — доступный остаток самого процесса и его предков, диск — shutil, CPU — system API и `/proc/cpuinfo` при наличии. Батарея None и неизвестные инструкции означают «неизвестно», а не отсутствие. Для Android системная RAM не является лимитом приложения: пока ActivityManager не интегрирован, безопасный подбор отключён и возвращает `unavailable`. cgroup v1 и нестандартное расположение монтирования cgroup не поддержаны; не считать бюджет безопасным в таких окружениях. На Windows/macOS флаги CPU могут быть неизвестны. Замороженный исполняемый файл не поддерживает запуск пробника.

FP32 matmul выполняется одним потоком BLAS; далее один реальный шаг NumPy ModelForge с синтетическими токенами и seed 42 проверяет изменение весов. Кандидаты запускаются последовательно отдельными процессами, с общим и индивидуальным тайм-аутом. Приблизительная модель памяти: 16 байт/параметр для весов, градиентов и состояний AdamW плюс эвристика активаций; она **не** включает все временные буферы. Родитель опрашивает RSS каждые 10 мс, прерывая процесс при превышении бюджета; на Linux/macOS пик дополнительно получается из `ru_maxrss`. Это не жёсткий лимит: быстрый скачок может вызвать OOM раньше опроса, конкурентные процессы меняют доступную память. Не запускайте на устройствах с риском потери данных. Резерв 35% — настраиваемый запас, а не гарантия безопасности.

Максимум — лишь максимальный **прошедший из заданного списка**, для конкретных архитектуры, batch и context, а не предел устройства. Оценка эпохи равна времени одного шага × указанному числу шагов и не учитывает загрузку данных, валидацию и тепловой троттлинг. Fine-tuning и inference не измеряются, удалённое выполнение — только рекомендация. Никакого датасета при пробе нет; это не обучение модели и не оценка качества.

Старые статические ограничения `PlatformInfo` по-прежнему применяются в конструкторе и обучении для обратной совместимости; измеренный максимум автоматически их не заменяет. План миграции: после проверки на реальных Android/Windows/macOS устройствах внедрить достоверный лимит приложения и безопасную изоляцию, сравнить результаты с прежними ограничениями, добавить явный opt-in и только затем менять политику. До этого отчёт — диагностический, не обещание доступности обучения. Low Memory Mode при вызове через core/builder/engine отмечается в отчёте, существующие ограничения остаются в силе.

## Замер текущего окружения

Сохранён сырой отчёт `CAPABILITIES_MEASUREMENT_2026-11-28.json`. Команда:

```
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m modelforge.cli.main --home /tmp/modelforge-capabilities doctor --capabilities --output docs/CAPABILITIES_MEASUREMENT_2026-11-28.json
```

Конфигурация и все результаты содержатся в JSON. Использовался синтетический RNG seed 42, данные генерируются в процессе, отдельного датасета или test split нет. Замер выполнен на рабочем дереве поверх `12718d1` (незакоммиченные изменения capability-модуля); версии Python и NumPy и хеши исходников указаны ниже. Отрицательные результаты сохраняются в `candidates`, а при прерывании последующие размеры не считаются проверенными.
