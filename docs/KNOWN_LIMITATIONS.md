# Известные ограничения, риски и статус проверок (v1.0.0)

В соответствии с правилами инженерной честности ModelForge AI здесь перечислены все реальные границы текущей реализации:

## 1. Масштаб локального обучения
- Встроенный тензорный движок обратной автодифференциации (`modelforge.architectures.tensor_engine` поверх `NumPy`) спроектирован для **компактных и экспериментальных моделей** (от десятков тысяч до нескольких миллионов параметров на CPU и мобильных ARM64 устройствах).
- Обучение крупных моделей (сотни миллионов и миллиарды параметров) на смартфоне или без дискретного GPU **не обещано и заблокировано** лимитами `Low Memory Mode`. Для более крупных моделей предусмотрены опциональный `PyTorch` адаптер (`pip install -e ".[torch]"`) и `Remote / Hybrid Mode`.

## 2. Доставка Python на Android ARM64
- Экран быстрого старта Android использует встроенные CPython/NumPy (Chaquopy), без сети и сервера. Полное Python-ядро, остальные разделы и совместимость с его реестром в APK не встроены: для них по-прежнему нужен Termux или сервер.

## 3. Подпись сборок Android и macOS
- В репозитории не хранятся приватные ключи подписи.
- Если в GitHub Secrets не заданы `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` и `ANDROID_KEY_ALIAS`, CI собирает `ModelForge-Android-ARM64.apk` и `.aab` с тестовой отладочной подписью (фиксируется в `ModelForge-Android-ARM64.SIGNING_STATUS.txt`), которая подходит для ручной установки и проверки, но требует релизной подписи перед публикацией в Google Play.
- Сборка `ModelForge-macOS.dmg` выполняется без платной нотаризации Apple Developer ID (фиксируется в `ModelForge-macOS.SIGNING_STATUS.txt`).

## 4. Изоляция запускаемого кода
- Модуль `run_restricted_python` запускает код и тесты в изолированной директории с очищенными переменными окружения, жёстким таймаутом и системными лимитами POSIX `RLIMIT_CPU` / `RLIMIT_AS`. Это явно маркируется как `restricted_subprocess` и не заменяет аппаратную виртуализацию / microVM при запуске враждебного кода.

## 5. Разделение автоматических CI-проверок и физических устройств
- Сборки и тесты проверяются в автоматизированных окружениях Linux x64, Windows x64, macOS и Android ARM64 Gradle CI.
- Физическая установка APK на конкретный реальный смартфон с 3 ГБ RAM, интерактивное тестирование GUI на физическом экране смартфона, а также платные облачные GPU-адаптеры и коммерческие ключи внешних провайдеров (`OpenAI`, `Composio`) требуют наличия у пользователя соответствующего физического устройства или учётных записей.

## 6. Будущие возможности (заложены архитектурно, НЕ реализованы в MVP)
- Мультимодальное обучение (изображения/аудио/видео) — `NOT IMPLEMENTED IN MVP`.
- Автоматическая аренда платных облачных GPU — `NOT IMPLEMENTED IN MVP`.
- Автоматическое самопереписывание ядра без подтверждения пользователя — намеренно отключено политикой безопасности.

## 7. Повторные проходы трансформера

В Python-ядре для `decoder_transformer` и `tiny_transformer` можно задать
`loop_passes` от 1 до 8. Один и тот же набор блоков применяется повторно и при
обучении, и при генерации; градиенты проходят через все повторения. Значение
сохраняется в спецификации и чекпоинте. Старые модели используют один проход.
Это экспериментальная архитектура, не гарантия рассуждений или качества
ведущих моделей: больше проходов увеличивает время вычислений и расход памяти.
GGUF-экспорт таких моделей отключён, поскольку совместимый исполнитель для
него не реализован; используйте чекпоинт ModelForge. Данные safetensors — только
веса с метаданными, а не самостоятельно исполняемая модель.

На Android быстрый старт обучает очень маленький символьный трансформер на CPU
(не более 20 000 символов ввода, ограниченное число шагов и ориентировочно до
90 секунд). Целевой вес является верхней границей; фактическая модель может
быть значительно меньше. Поле назначения сохраняется в метаданных, но само по
себе не добавляет знания. Качество не сопоставимо с большими языковыми моделями.

Сохраняется только последняя локальная модель в приватной папке приложения; новое
успешное обучение её заменяет. Возобновление, экспорт и перенос в реестр полного
ядра не реализованы. Закрытие приложения или завершение процесса ОС может прервать
обучение; гарантии фонового выполнения нет. На ПК быстрый старт использует
входящий в дистрибутив локальный backend, а не Android-движок. Автопоиск внешних
данных не реализован: нужны тексты пользователя.

Android APK/AAB собирается для ARM; тренировку и генерацию проверяет Android
x86_64-эмулятор в CI. На физическом ARM-смартфоне функция пока не проверена.

## Capability probe

See [CAPABILITIES.md](CAPABILITIES.md). Android application memory limits are not integrated, so Android probing is disabled; a physical phone and thermal behaviour have not been verified. RSS polling is not an enforceable hard memory limit, cgroup v1 and nonstandard mounts are not covered, and measured maxima do not replace the legacy static builder/training limits. Frozen builds cannot run the subprocess probe. A single synthetic step is not full training.
