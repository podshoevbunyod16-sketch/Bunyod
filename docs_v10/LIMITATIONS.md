# LIMITATIONS.md — v0.10 (известное; ничего не «закрыто статусами»)

## Производительность (host, измерено; см. BENCHMARK_REPORT)
- p95/p99 точечного поиска НЕ догоняют in-RAM dict (~5–10× на 100k): структурный пол
  чистого Python (bisect+unpack+вызов ≈1.8–2.7 µs против 0.37–0.8 µs dict). Целевой
  FAIL из v0.9 (≤2×) сохранён; компилируемые пути запрещены версией.
- partial-запросы на array-корзинах МЕДЛЕННЕЕ dict-варианта на малых n (2.5 vs 1.4 µs
  @10k — копия array→list на маленький бакет); выигрыш появляется от ~1M (166 vs 275 µs).
  Мелкие БД остаются на v0.8-путях при желании.
- журнал удешевляет update, но open() платит replay-ом кадров: кривая — в матрице;
  политика compact-порогов — рекомендация, не автоматика.
- mmap быстрее pread на маленьких кэшах и ХУЖЕ по p95 на больших (page-fault джиттер).
- LRU горячих ключей окупается только на skew (repeat/zipf); на uniform — минус 5–25%.

## Надёжность/безопасность
- журнал защищён от разрывов и дублей, но НЕ от злонамеренного содержимого кадров
  (crc кадра проверяется; семантика value — как есть).
- on_bad="skip" продолжает работу с дырами в данных — только для чтения «как есть».
- compact: атомарен через os.replace, но оставляет .new/.building при внешней гибели
  процесса (мусор, не порча; тесты это фиксируют).

## Платформы
- ВСЕ host-числа: Linux x86-64, 2 CPU/2 GB, /tmp=tmpfs ⇒ fsync-цифры оптимистичны;
  на flash устройства гейт ≤5 ms остаётся INCONCLUSIVE до извлечения устройствых JSON
  (команда в rasm_cim_v9/mobile/README_v09.md) и r3-прогона RSS.
- Термальные sysfs на устройстве отсутствуют → троттлинг-корреляция невозможна
  (задокументировано, не выдумано). Разброс p95 между прогонами (0.101→0.154 мс @100k
  legacy) не атрибутирован.
- Python 3.14 — не проверялся (среда 3.13.18); код stdlib-only ≥3.10.

## Упаковка (production-заготовки и что ещё нельзя)
- `pip install -e .` + console-script `rasm-cim-demo` проверены; **wheel-сборка** — нет
  (v0.8-дерево без __init__.py; трогать frozen-файлы нельзя ⇒ решение о ре-пейкинге
  v0.8-обвязки отложено, это не блокирует работу из дерева).
- requirements-core нет намеренно (0 runtime-зависимостей; numpy — опция).
- CLI покрывает storage-ядро; единый `python -m rasm_cim` (§7 промпта) появится со
  слоем языка (v0.11+), чтобы не плодить вторую точку входа.

## Не реализовано (следующие версии, по промпту)
Всё языковое: нормализация/токенизация/типы запросов (v0.11), Concept/Entity/Relation
сверх v0.4-графа + источникове происхождение фактов (v0.12), диалоговый контекст и
местоимения (v0.13), конвейер «вход→ответ» с evidence-linking (v0.14), обучение/корпус
200–500 + независимый тест-набор (v0.15). Никаких заявлений о «понимании языка» не
делается: подтверждённая область v0.10 — детерминированный поиск по памяти +
контекстно-независимые запросы.
