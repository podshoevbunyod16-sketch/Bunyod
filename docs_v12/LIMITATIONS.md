# LIMITATIONS.md — v0.12

1. **Хранилище — текстовый JSONL event log**, не индексная БД: replay O(#событий) на
   open; годится для прототипа и корпусов ≤ ~10⁵ событий; для больших объёмов нужен
   снапшот/индекс (не делалось — см. PLAN_NEXT).
2. **Синонимы**: только явные алиасы и рус.→канон таблица предикатов; нет автоматического
   вывода синонимии и нет стемминга для канонизации предикатов вне таблицы.
3. **Алиасы**: контроль неоднозначности есть (AMBIGUOUS + candidates), но разрешение
   требует явного type_hint или канонического имени — UI-подсказка «уточните» не
   реализована (это v0.13 диалоговый слой).
4. **Provenance.position** заполняется только если источник фрагмента известен
   (ad-hoc teach → None); выравнивание фрагментов с документами — вне объёма.
5. **Конфликты не разрешаются автоматически** по замыслу; функциональная семантика
   только для списка FUNCTIONAL_PREDICATES (capital_of, population_of, height_of,
   director_of, ceo_of, governor_of) — остальные предикаты нефункциональны и
   многозначны by design.
6. **status_for без object** для нефункциональных предикатов возвращает «TRUE если есть
   ≥1 active assert» — грубая сводка; точный ответ — set-valued через query_statements.
7. **Reliability — категориальная** (low|medium|high), не калиброванная числовая шкала;
   калибровка — вне объёма (см. v0.14/v0.15).
8. **Import**: entity_alias_added для неизвестной сущности в mid-file → skip + replay_errors;
   seq/ts при импорте переназначаются (provenance сохраняется); порядок событий важен.
9. **Конкурентная запись в один KB из нескольких процессов НЕ поддерживается**
   (нет блокировок; append+fsync гарантирует целостность строк, не сериализацию tx).
