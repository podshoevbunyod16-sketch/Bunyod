## 2. Что из задания НЕ подтвердилось (важнейшая часть аудита)

Задание исходило из предположения, что в проекте уже есть разговорная база
знаний с файлами `~/.rasm-cim/kb.json`, `~/.rasm-cim/context.json`, командами
`teach`, отношением `is_a` и накопленными данными пользователя.

**FACT (проверено grep'ом по всему репозиторию до начала работ)** — совпадений
по `kb.json`, `context.json`, `.rasm-cim`, `teach`, `is_a` в исходном коде
**ноль**.

**FACT** — каталог `~/.rasm-cim/` в этом окружении **не существует**.

**RESULT / следствие** — миграция со «старого» формата не могла быть проверена
на реальной пользовательской базе: её здесь нет. Поэтому:

1. Формат v1 описан и реализован как **входной контракт** мигратора
   (`rasm_cim_v16/migrate.py`), а не как прочитанный из репозитория факт.
2. Все тесты миграции работают на **синтетической** базе v1, созданной тем же
   модулем (`write_legacy_sample`) и записанной на диск. Это проверяет код
   миграции, но **не** проверяет совместимость с чьей-то реальной базой.
   Статус этой части: **INCONCLUSIVE по реальным данным**, **RESULT** по коду.

**FAIL (в документации, не в коде)** — в `docs_v2…docs_v10` описаны
возможности, которые в коде v0.9 отсутствуют (например, разбор русских
предложений). Документация не является доказательством; проверка шла только по
коду.

## 3. Что реально умела система до v0.16

**FACT** — `rasm_cim_v9/graph.py` реализует `TruthGraph9`: трёхзначная
полярность (true / false / unknown), субъект-предикат-объект как **целочисленные
id**, поддержка отрицаний и противоречий на уровне ячеек. Это единственный
механизм хранения знаний, и он работает (покрыт `tests_v9`).

**FACT** — `rasm_cim_v9/memory/store9.py` — запись/чтение состояний памяти,
`rasm_cim_v9/storage/index.py` — индексы. Ни один из них не разбирает
естественный язык.

**FACT** — разбор входной строки в v0.9 отсутствует: CLI v0.9 принимает
готовые тройки/команды, а не русские предложения.

**RESULT** — вывод аудита: v0.16 — это **новый языковой и семантический слой
поверх замороженного субстрата**, а не переписывание проекта. `TruthGraph9`
используется как зеркало полярности (лениво, по требованию), все исторические
деревья не импортируются на запись.

## 4. Ограничения окружения, влияющие на приёмку

**FACT** — в песочнице доступен только **Python 3.11.2** (`python3 -VV`);
интерпретаторов 3.10 / 3.12 / 3.13 / 3.14 нет, сетевой доступ ограничен
списком хостов (github, pypi, npm), поэтому собрать CPython 3.14 нельзя.
→ Требование «проверить на Python 3.14 отдельно»: **INCONCLUSIVE** (см.
V016_LIMITATIONS.md). Вместо запуска выполнена статическая проверка
совместимости с 3.10-синтаксисом (`tests_v16/test_k_portability.py`).

**FACT** — архитектура `x86_64`, устройство Android/Termux недоступно.
→ Требование «запуск на ARM64/Termux»: **INCONCLUSIVE** на реальном
устройстве; **RESULT** по проверяемым предпосылкам (только stdlib, нет сети,
нет абсолютных путей, нет тяжёлых зависимостей).

**FACT** — системный `python3 -m pip install` блокирован PEP 668; используется
локальное окружение `.venv` (pytest 9.2.0, hypothesis). Это окружение
сессионное и в репозиторий не коммитится.
