## Что этот отчёт НЕ говорит

1. **38 реплик — это мало.** Доверительный интервал на таком объёме широкий:
   «97 %» здесь означает «примерно 95–99 % на похожих фразах», а не «97 % на
   любом русском».
2. **Корпус написан авторами кода.** Он проверяет регрессии и вскрывает
   конкретные дефекты (что и произошло: h01, h05, h06, i22), но он не является
   независимой оценкой. Независимый корпус — задача следующего шага.
3. **unsupported rate = 0 % — структурный факт**, а не гарантия правдивости:
   он означает, что у каждого факта в ответе есть строка в журнале источников.
   Он не означает, что источник верен.
4. **Кореференция измерена на 5 отсылках.** Это проверка того, что механизм не
   врёт (0 ошибочных связок), а не оценка качества разрешения местоимений:
   для неё нужен корпус на порядок больше.
5. **Нет замеров на ARM64/Termux**, нет Python 3.14, нет сравнения с внешними
   системами (внешние LLM в проекте запрещены как генератор).

## Воспроизводимость

* корпус и seed лежат в репозитории, sha256 печатается в отчёте;
* демо-база строится только через `teach` и импорт Плана A — прямых записей в
  граф нет (`rasm_cim_v17/semantics/harness.py`);
* метрики считаются на том же `SemanticPipeline`, который обслуживает CLI
  (`rasm_cim_v17/pipeline.py`), а не на отдельной «измерительной» копии;
* регрессионный порог закреплён тестом
  `tests_v17/test_plan_b_metrics.py::test_baseline_metrics_do_not_regress`:
  снижение чисел валит сборку.

Измеряется `python -m rasm_cim metrics` (семья `evidence`) на демо-базе:

|---|---|---|
| точность источников (corpus + пробы) | **1.0** | у каждого из 42 фактов в ответах есть запись об источнике |
| выведенных фактов среди них | 13 | ответы с цепочкой, а не с одной строкой |
| покрытие посылок доказательств | **13/13 = 1.0** | у каждой посылки вывода есть строка источника |
| ответов без источника | 0.0 % (0/38) | — |

Фиксированные пробы вывода (`INFERENCE_PROBES` в `semantics/metrics.py`):
«Где находится Париж?», «Кто написал Евгений Онегин?», «Кто такой Кит?».
Они вынесены из корпуса намеренно: числа Плана B (38 кейсов, sha256
`743c8c18…`) не должны меняться из-за новых измерений.

Что эти числа **не** говорят: они не показывают, что вывод корректен за
пределами демо-базы. Правила вывода — правила v0.16 (`inverse`, `transitive`,
`instance_subclass`, `symmetric`, `alias_bridge`) с затуханием уверенности;
проверялся только один транзитивный шаг и одно обратное прочтение. Цепочки
длины 4+ в тестах не участвуют, потому что политика (`max_answer_depth=3`)
такие факты в ответ не пускает.
