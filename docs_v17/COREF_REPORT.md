# Этап 1. Кореференция: наборы, метрики, результаты

Статус: **VERIFIED** для заявленных наборов; обобщение за их пределы —
**INCONCLUSIVE** (см. «Ограничения»). Все числа получены прогоном
`python -m rasm_cim coref-bench` на коде ветки `arena/72c9200d-bunyod`.

## 1. Что считается

Кейс — короткий диалог: `facts` (обучающие реплики, дословно в базу), затем
`turns`; оценивается последняя реплика. Ожидание задаётся рубрикой:

| `expected`  | верно, если |
|-------------|-------------|
| `REFERENT`  | местоимение связано именно с `entity` из разметки |
| `RECENCY`   | связано с последним из двух кандидатов |
| `REFUSE`    | связки нет (система переспросила), а не «угадала» |

Метрики (имя → определение):

* **связка на уникальный антецедент** — `correct / n(REFERENT)`;
* **выбор по свежести** — `correct / n(RECENCY)`;
* **правильный отказ** — `refused / n(REFUSE)`;
* **необоснованные связки** — доля `REFUSE`-кейсов, где система всё-таки
  связала (`ungrounded_rate`);
* **ошибочные связки** — связала, но не с тем (`wrong_bindings`);
* **отказы при живом референте** — `refused` там, где был `REFERENT`/`RECENCY`;
* **итоговая безопасная точность** — доля кейсов, где система либо дала верную
  связку, либо честно отказалась; ошибка и необоснованная связка считаются
  нулём. Это главная цифра, потому что «угадал половину» здесь хуже отказа.

Все доли даны с 95 % интервалом Уилсона (не нормальным приближением — при
малых n и долях у 100 % он врёт).

Ровно 100 % на всех шести запечатанных сплитах — это **не** свидетельство
решения задачи кореференции: наборы синтетические, построены генератором из
13 конструкций, и механизмы (исправление, «они», класс-дистрактор, длинная
дистанция) доводились на dev/validation **этих же конструкций**. Что эти цифры
действительно показывают: реализованные правила срабатывают на всём объёме
13 конструкций, не ломаются на новых сэмплах и **ни разу** не дали
необоснованной связки. Чего они не показывают — переноса на свободную речь.

### Парафразы (написаны после запечатывания hidden)

12 вручную составленных кейсов с другими формулировками: «Он ведь писатель?»,
«Правда ли, что он физик?», «Я говорил про Куприна», «Точнее, Куприн»,
«А теперь про Куприна» и т. п. Это **диагностика**, не оценка: они написаны
после того, как hidden был зафиксирован, и уже поэтому не могут служить
несмещённым измерением. Динамика по ходу работы:

| состояние | безопасная точность | что сломалось |
|-----------|--------------------|----------------|
| до правок по парафразам | 8/12 = 66.7 % | «А теперь про X» не распознавалось; «Я говорил про X», «Точнее, X» не считались исправлением |
| после расширения маркеров | 10/12 = 83.3 % | «Точнее, X» всё ещё не срабатывало (экранирование в шаблоне) |
| после исправления шаблонов | 11/12 = 91.7 % | остался 1 отказ: «Правда ли, что он физик?» — связка не найдена, система переспрашивает |

Оставшийся отказ — честный: конструкция «Правда ли, что …» не разбирается
парсером v0.16, местоимение остаётся неразрешённым, ответ — уточнение, а не
догадка (0 ошибочных связок). Чинить парсер v0.16 нельзя по условию задачи.

## 4. Как воспроизвести

```bash
python -m rasm_cim coref-bench --split dev                  # v1 dev
python -m rasm_cim coref-bench --split validation           # v1 validation
python -m rasm_cim coref-bench --split hidden --allow-hidden  # v1 hidden
python -m rasm_cim coref-bench --dir tests_v17/corpus/coref2 --split dev
python -m rasm_cim coref-bench --dir tests_v17/corpus/coref2 --split hidden --allow-hidden
python -m rasm_cim coref-bench --dir tests_v17/corpus/coref_paraphrase.jsonl --split probe
pytest -q tests_v17/test_stage1_coref_bench.py             # 23 теста
```

`--json` пишет отчёт в stdout (перенаправляйте в файл, не в канал с python).

## 5. Что именно добавлено в систему

Ядро v0.16 не тронуто (`git diff be5551ea -- rasm_cim_v16 tests_v16 docs_v16`
пуст). Всё новое — в `rasm_cim_v17`:

* `semantics/morphology.py` — словарная форма без морфологического словаря:
  снимает падежные окончания, разрешает только при статусе
  `EXACT/ALIAS/NORMALIZED/MORPHOLOGICAL`, при двух разных сущностях на одну
  форму — отказ (иначе «Анну» стало бы «Анна» или «Анной» наугад);
* `discourse/correction.py` — маркеры исправления и переключения темы
  («нет, я про X», «не A, а B», «точнее, X», «я говорил про X», «речь о X»,
  «а теперь про X»), ответ-подтверждение и перенос фокуса;
* `discourse/binding.py` — `explicit_focus` (исправление переживает ход
  контекста), отказ от связки с классом (`PRONOUN_DENIED_KINDS`), отказ для
  «они» при двух и более кандидатах, связка только на сущность, **прозвучавшую
  в этом диалоге** (иначе «она» после одной реплики уходила в предзагруженную
  «Англию»), запасной пул по salience+роду, когда замороженный резолвер
  выбирает класс;
* `discourse/coref_bench.py` — генератор двух наборов, оценка, Уилсон,
  манифест и проверка запечатывания;
* `semantics/meaning.py`, `pipeline.py` — поле `MeaningIR.correction`,
  детекция исправления до парсера (парсер режет «Нет, не Иван, а Мария» на два
  смысла), подтверждение-ответ.

## 6. Ограничения

1. **Синтетика.** Все шесть сплитов — из одного генератора, 13 конструкций,
   фиксированные банки имён и классов. 100 % на них не переносится на свободный
   текст; парафразы (91.7 %, n=12, ДИ 64.6–98.5) показывают, что цифра падает
   уже при смене формулировки.
2. **Демо-база.** Оценивается одна и та же база знаний (~60 сущностей). Другая
   база — другие salience-конфликты, не проверено.
3. **Один прогон hidden.** Hidden оценивался после правок, найденных на
   dev/validation/парафразах; cases hidden при отладке не просматривались, но
   «порог» подбирался на родственных конструкциях. Независимой проверки нет.
4. **Одиночные местоимения.** Проверены «он», «она», «они». Притяжательные
   («его», «её»), указательные («этот», «тот») и эллипсис длиной 4+ реплики не
   покрыты — INCONCLUSIVE.
5. **Разбор реплик.** Дефекты парсера v0.16 («Который час?», «X и Y — физики?»,
   «Правда ли, что …») не исправлялись: они вне Этапа 1, но именно они дают
   оставшиеся отказы.
