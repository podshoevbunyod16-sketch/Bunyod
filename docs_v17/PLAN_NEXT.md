# PLAN_NEXT — что делать после Плана A

Порядок соответствует PDF-роадмапу (фазы 2–8). Каждая фаза заканчивается
коммитом, полным регрессионным прогоном и обновлением `PROGRESS.md`.

## Фаза 2 — План B: семантический pipeline (QueryIR → MeaningIR)

Цель: отделить «что сказано» от «что спрошено» и начать **измерять**.

1. `rasm_cim_v17/semantics/meaning.py` — `MeaningIR` поверх `QueryIR` v0.16:
   речевой акт, фокус, ожидаемый тип ответа, пресуппозиции, область
   неопределённости. `QueryIR` не меняется (он — контракт v0.16).
2. `rasm_cim_v17/semantics/metrics.py` — intent accuracy, entity extraction
   precision/recall, доля «не понял», unsupported-answer rate.
3. `tests_v17/corpus/` — **размеченный** мини-корпус (вопрос/интент/сущности),
   явно описанный в TEST_REPORT: сколько примеров, кто размечал (мы), какая
   цена ошибки. Никаких «99 %» на трёх примерах.
4. Критерий приёмки: метрики печатаются командой
   `python -m rasm_cim metrics --corpus …`, значения попадают в TEST_REPORT,
   ни одна метрика не заявляется без числа и объёма выборки.

## Фаза 3 — План C: контекст и coreference

`rasm_cim_v17/discourse/context.py`: разрешение местоимений и эллипсиса с
явными правилами отказа («два кандидата → спросить»), метрика coreference
accuracy на корпусе из Фазы 2.

## Фаза 4 — План D: reasoning с доказательствами

Ядро v0.16 уже возвращает `Fact.proof` и `EvidenceSet`. Задача v0.17 —
не переписать вывод, а (а) ограничить глубину/ветвление политикой, (б) считать
evidence precision (доля ответов, где каждое предложение имеет источник),
(в) добавить регрессионные сценарии на цепочки длиной 3+.

## Фаза 5 — План E: связная генерация

`discourse/planner.py` (DiscoursePlanner) → `ResponseIR` → NLG-рендерер.
Жёсткое ограничение: рендерер получает **только** факты с evidence; любая
фраза без источника — дефект, а не «стиль».

## Фаза 6 — План F: обучение без разрушения знаний

`rasm_cim_v17/learning/`: версии артефакта с `parent`, sha256, метриками до/после
и откатом по указателю. Схема должна остаться совместимой с
`rasm-cim-learned/1`, чтобы артефакт читался обеими линиями (см.
`interop/learned.py`). Инвариант: обучение не пишет в `kb.json`.

## Фаза 7 — План G: надёжность, Termux, производительность

* fuzz/повреждения: обрезанный `kb.json`, битый ledger, огромный импорт;
* замеры на ARM64/Termux (иначе — честное INCONCLUSIVE, как сейчас);
* бюджеты: время ответа, память, размер базы; никаких заявлений без замера.

## Фаза 8 — финальная верификация

Прогон всех наборов, сверка каждого числа в документах с командой, которая его
получает; отдельный раздел «что не проверено» переносится в LIMITATIONS без
сокращений.
