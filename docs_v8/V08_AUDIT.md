## 2. Ключевые находки аудита, определяющие v0.8

1. **Формат v1 пригоден для постраничного чтения частично**: заголовок
   (4+4+8) даёт count без payload; но ОДИН чексум на весь payload ⇒
   частичная проверка целостности невозможна. v0.8 вводит **формат v2**
   (per-page checksum) как надстройку; v1 остаётся read/write-совместимым.
2. **Плановые цели M2 (RSS < 40 MiB, p95 ≤ 2×) достижимы только если
   HV-представление не float64[256]**: float HV = 2 KB/запись ⇒ 100k = 200 MiB
   ещё до индексов (это и есть главный ограничитель Python-памяти). Отсюда
   связь M5→M2: bit-packed ±1 HV (32 B/запись) — единственный переносимый
   путь в мобильный бюджет; в v0.7 эта ветка была отложена (NON_PORTED #4).
3. **Inverted index (97/89/83) — второй по весомости потребитель памяти**
   (3 набора по N ключей; в Rust v0.7 ~135 мс build на 100k). Для 1M в
   Python его размер надо измерять отдельно (M6 требует именно этого).
4. **GIL**: v0.7 замерил «rayon put 0.87×» на 2 CPU; для Python v0.8 честный
   аналог — сравнение threads/processes/asyncio на тех же задачах (M3/M7),
   ожидание: CPU-bound потоки НЕ ускоряются (GIL), процессы ускоряются с
   платой сериализации; это надо измерить, не заявлять.
5. **rule110 legacy-расхождение** (ERRORS #7): Python-таблица ca4.py ≠
   каноническая 110. Исторические результаты v0.4 не трогает (тамошний CA —
   rule 90). v0.8: `rule110_canonical` флаг, legacy по умолчанию, тесты на
   все 8 комбинаций.
6. **Atheris доступен в этой среде** (pip install успешен; pure-Python
   цели инструментуются байткодовым хуком Atheris) ⇒ M4 может дать
   НАСТОЯЩИЙ coverage-guided fuzzing, а не только property-based. Гипотеза
   тоже установлена (6.170.17). Numba 0.66.0 есть ⇒ M5 с JIT-веткой.
7. **Нет thermal sysfs/cpufreq на хосте** ⇒ M1 «температура/throttling» не
   измерима здесь; в мобильный пакет войдут best-effort считыватели с
   явной пометкой, где данные недоступны. Реального Android-устройства в
   песочнице нет ⇒ M1 остаётся ОТКРЫТЫМ (пакет+инструкции — да; замеры —
   нет; статус не объявляем завершённым).
8. **1M записей vs 1.9 GiB RAM**: float-HV-память не влезет никогда;
   packed-store + bitpack-HV + streaming — влезают; M6 обязан это
   подтвердить фактическим прогоном, а не экстраполяцией 100k.

## 3. Что НЕ меняется

- Ни один файл v0.1–v0.6; ни один файл `rasm_cim_rust/` (кроме чтения);
  исторические JSON/график-артефакты; результаты бенчей v0.7.
- В v0.8 Rust НЕ импортируется в рантайме (исключение — генерация
  golden-bytes для кросс-версионного теста формата, офлайн, одним прогоном
  замороженного CLI; это oracle, а не вычислительная ветка).
