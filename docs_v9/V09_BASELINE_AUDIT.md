## 1. РЕАЛИЗОВАНО (код есть, структура подтверждена чтением)

Слой v0.9 (1095 строк, 6 файлов, только stdlib):
- `rasm_cim_v9/storage/index.py` (209) — компактный индекc: `sort_to_arrays`
  (tuples|order|numpy; numpy lexsort со знакомым трюком `view(uint64)^SIGN` для
  отрицательных int64; авто: numpy только при n≥200k и импортнутом numpy),
  `ResidueIndex` (dict→array('q') корзины из уже отсортированных ключей, моды 97/89/83),
  `build_v3_base` (генераторный ввод, ровно 2 плоских массива резидентно, commit =
  заголовок 40 B с CRC в конце + `os.replace`), `read_v3_header`.
- `rasm_cim_v9/storage/journal.py` (373) — журнал v3: кадры `<QII(seq,count,crc32)>`,
  `append_txn` (авто-seq, пропуск `seq<=last`, header-only walk за last_seq — O(#кадров)),
  `V3Store` (база array q/Q + журнальные представления file/sorted, bisect-get,
  torn-tail игнор, `JournalCorruptError` при bad-crc с преемниками, `on_bad=skip|raise`,
  режимы pread|mmap, `build_residue` через heapq.merge), `open_any` (v1/v2/v3), `compact`.
- `rasm_cim_v9/storage/hotlru.py` (55) — LRU горячих ключей (байт-бюджетный, над ответами).
- `rasm_cim_v9/memory/store9.py` (159) — `MobileMemory9`: ярусы stream/residue/hv,
  update=txn в журнал, `query_exact/partial/noisy`, `open_hv_stream|legacy` (A/B сохранён).
- `rasm_cim_v9/graph.py` (97) — `TruthGraph9`: формализованная семантика assert/retract
  в docstring, режимы symmetric (новый default) / legacy (≡v0.4).
- `rasm_cim_v9/mobile/` (202+скрипты) — Termux A/B харнесс r3 (изоляция arms
  subprocess-ами), README, setup/run .sh.
Наследие v0.8, на которое v0.9 опирается импортами (read-only): `storage/format.py`
(v2 write/read, page_sum crc32), `storage/streaming.py` (LazyStore: resident index уже
array q/Q — вывод M0: не переоптимизировать), `memory/stream_memory.py`, `hv/bitpack.py`,
`memory/hv_stream.py` (gen/block/block_numpy/combo/auto; LRU исключён из auto по замеру).

## 2. ПРОВЕРЕНО (есть тесты/замеры в results_v9, значения подтверждены свежим чтением JSON)

- Форматная совместимость: v1/v2 читаются `open_any`; v2→v3 миграция даёт идентичные
  ответы; v3 data-pages = v2-страницы (сдвиг 40 B); золотые хэши v1/v2 не тронуты.
- Crash-consistency: SIGKILL-инъекции на 3 стадиях записи (partial body / header-only /
  разрыв посреди 60 append-ов) → повторное открытие чистое, база не загрязнена,
  последний commit-кадр цел; повторный replay не дублирует (dup seq пропускается);
  bad-cpc в середине с преемниками → контролированная ошибка.
- Производительность ядра (host, изолированные процессы, результаты_v9/m1_m2.json):
  сборка @1M VmHWM 88.3 vs v0.8 141.8 MiB (−38%); residue @1M +27.3 vs +72.2 MiB (−62%);
  partial @1M p50/p95 165.7/188.2 vs 274.5/378.4 µs; exact-lookup паритет (16.5/22.3 µs);
  update @1M медиана 0.032 ms (fsync) — PASS с оговоркой tmpfs; регрессия small-n partial
  (2.5 vs 1.4 µs @10k) — сохранена и документирована.
- Языковая корректность семантики (не NLU!): `get`-семантика UNKNOWN/CONFLICT(отсортир.
  множество)/TRUE совпадает с v0.8; ResidueIndex == v0.8 query_partial по 97/89/83.
- Фаззинг/свойства: atheris 5 целей (header чистый 6.32M прогонов; journal/records —
  2 бага, исправлены, после фикса чисто 732k/461k; corruptmid 1.23M; compact 827k),
  5 hypothesis-свойств; оба найденных бага имеют регрессионные тесты с точными байтами.
  Учтён учётный пробел: `fuzz_atheris.json` был перезаписан последним 2-целевым прогоном;
  в этом сеансе создан `results_v9/fuzz_atheris_full.json`: СВЕЖЕОДНОРАЗОВЫЙ ре-прогон
  ВСЕХ пяти целей (по 60 с: header 3.02M, journal 382k, records 239k, corruptmid 608k,
  compact 431k прогонов; все rc=0 — новых находок нет, два crash-артефакта исторические,
  под регрессиями). Старый `fuzz_atheris.json` не переписывался.
- TruthGraph9: 12 тестов, исчерпывающие последовательности операций L≤5 (7776) против
  независимой теневой модели; legacy-режим ≡ замороженному v0.4 на всех последовательностях L=4.
- Реальное устройство (отделено от host!): `results_v9/device/DEVICE_RESULTS_PASTED.json` —
  транскрипт пользовательского Termux-прогона (ядро 4.9.77+, частота 2001 МГц читается,
  temp-sysfs отсутствует = null, не авария): 4 прогона (20k×2, 100k×2), parity picks
  20/20 во всех arms (семантическая эквивалентность на ARM64 подтверждена), mem9 лучший
  p95 @100k (0.107–0.112 vs legacy 0.121–0.179 мс); размер v3-файла на устройстве
  совпадает с host (3 200 824 B), резидентный индекс 16 B/rec.

## 3. ЧАСТИЧНО РАБОТАЕТ

- **M4 (устройство) — только PARTIAL**: не извлечены из сырых JSON на телефоне arms
  `v09_v3_store` и `v09_v3_journal_updates` (принтер пользователя фильтровал по «picks»;
  команда извлечения дана в README). RSS/peak-колонки r2-прогона **невалидны** (arms в
  одном процессе: аллокатор не возвращает память, VmHWM глобальный → все arms показали
  68.8 MiB @100k). r3-харнесс написан и проверен на host (5 изолированных arms,
  независимые 27.7–29.0 MiB) — устройствый r3-прогон не выполнен. Гейт ≤5 ms на flash —
  **INCONCLUSIVE** (host-tmpfs цифра не заменяет устройствую).
- LRU: реализован и измерен на 5 нагрузках (repeat ×6.57, zipf ×5.7, uniform ×0.95,
  full-scan ×0.75) — но оптимум по работе не зашит в auto-выбор намеренно; включается
  вручную; на устройстве skew-нагрузки не проверялись.
- mmap-режим: лучше pread при cache_pages≤8 (p95 −15%), **хуже** при cp64 (p95 4.13 vs
  2.64 µs, page-fault джиттер) — доступно, но не default; на устройстве не мерялось.
- `compact()`: корректен (ответы сохраняются), но для журнала мелких кадров почти не
  уменьшает размер (замеренное отношение ≈1.0) и стоит 1.45 s @1M.
- Пакетизация: v0.9 — namespace-пакеты без `__init__.py` (импорт с sys.path работает;
  `pip install -e` нет; requirements-файла нет — dev-зависимости (pytest/hypothesis/
  atheris/numpy-opt) нигде не задекларированы).

## 5. ОШИБКИ (найденные и зафиксированные; все исправлены в v0.9, с регрессиями)

1. **BUG-1 (библиотека)**: commit-заголовок v3 писался 44 B (лишний 4-B pad) и затирал
   младшие байты ключа первой записи страницы 0; маскировался при минимальном ключе 0 —
   поэтому ВСЕ ранние host-бенчи (facts от (0,·)) прошли незамеченными. Найден
   hypothesis P5 ДО atheris. Фикс: заголовок ровно HDR_SIZE. Все бенчи перезапущены
   после фикса (повторно замерено: числа раскладки не меняются — только данные корректны).
2. **BUG-2 (библиотека)**: `count` журнала (u32) не проверялся против размера файла до
   `pread(fd, count*16)` → MemoryError/DoS на враждебном хвосте. Найден atheris
   (краш-байты 8/16 B сохранены). Фикс: fstat-граница до аллокации; «хвост-обманка» →
   torn tail по R3.2.
3. **HARNESS-1 (тестовый код, не библиотека)**: утечка fd в fuzz-драйвере → EMFILE.
4. **Учётные пробелы (не код)**: (а) r2-устройственный харнесс перекрестно загрязнял
   RSS/peak — зафиксировано в отчёте, харнесс r3 написан; (б) `fuzz_atheris.json`
   перезаписан последним прогоном — восстановлен `fuzz_atheris_full.json`; (в) проекция
   v0.8 «~34.3 MiB @100k на устройстве» (host-дельта метод) оказалась неверна и
   официально снята.

## 6. ОГРАНИЧЕНИЯ

- Числа хоста ≠ числа устройства; tmpfs в песочнице ⇒ fsync-замер не показателен для
  flash (оговорка вшита в `M2_note_tmpfs` результатов). Устройственный апдейт-гейт —
  INCONCLUSIVE до r3/extraction.
- 2 CPU / 2 GB RAM / нет термальных сенсоров ⇒ p95/p99 джиттер (на телефоне тоже
  зафиксирован разброс: legacy @100k p50 0.101 vs 0.154 мс между прогонами — причинная
  атрибуция невозможна без temp; записано как аномалия, не объяснена).
- p95 ≤2× dict недостижим в чистом Python (пол ~1.8–2.7 µs против 0.37–0.8 µs; FAIL
  сохранён); пути улучшения без компилируемых частей ограничены.
- Гипотезы без подтверждения (не выдавать за факты): «LRU окупается на реальном
  телефоне»; «mmap выгоднее на flash»; «sidecar-индекс уберёт 0.29 s повтора журнала».
- Нет независимого языкового бенчмарка вообще — любые заявления о «понимании» запрещены
  промптом до §5-набора.
- Python 3.14 не тестировался; dev-зависимости не задекларированы; нет CI.
